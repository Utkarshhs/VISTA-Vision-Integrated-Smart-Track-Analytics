## SECTION 1: Project Context (Read First)

VISTA is a dual-portal predictive maintenance system for the Bangalore regional railway network. It uses:
- **Real-world geographic data** (OpenStreetMap) for all track and station coordinates.
- **A deterministic "ML Weights" formula** to calculate Component Integrity Index (CII) for 3,000 track nodes.
- **Gemini Flash API** strictly for live-demo image triage.
- **Server-Sent Events (SSE)** for real-time map updates during the demo.

The frontend already exists in a separate repo. Your job is to build, run, and verify the backend so the frontend can plug into it.

## SECTION 3: Setup — Step by Step

### Step 3.1: Install Dependencies

Open a terminal in the `/backend` folder and run:
```bash
npm install
```

This installs: `express`, `cors`, `dotenv`, `@turf/turf`, `firebase-admin`.

Verify it worked — you should see a `node_modules` folder appear.

---

### Step 3.2: Get the Map Data (GeoJSON)

This is critical. The entire data engine depends on this file.

1. Open a browser and go to: **https://overpass-turbo.eu/**
2. Delete all existing code in the left panel.
3. Paste this exact query:

```overpassql
[out:json];
(
  way["railway"="rail"](around:45000,12.9716,77.5946);
  node["railway"="station"](around:45000,12.9716,77.5946);
);
out body;
>;
out skel qt;
```

4. Click the **Run** button. Wait ~10 seconds. A blue starburst pattern should appear on the Bangalore map.
5. Click **Export** (top menu) → Under "Data" section → Click **GeoJSON**.
6. A file will download (likely named `export.geojson`).
7. **Rename it** to `railway-network.geojson`.
8. **Move it** into the `/backend/data/` folder. (Create the `data` folder if it does not exist.)

## SECTION 5: The Data Generation Deep Dive

### How Nodes Are Placed On Tracks

The script uses **Turf.js** library, specifically the `turf.along()` function. It works like this:

```js
// For each track line in the GeoJSON:
const lineLength = turf.length(track, { units: 'kilometers' });

for (let d = 0; d <= lineLength; d += 0.3) {  // 0.3km = 300m
  const point = turf.along(track, d, { units: 'kilometers' });
  // point.geometry.coordinates = [longitude, latitude]
}
```

This ensures every node sits exactly on the physical track line, including curves and zigzags. Intersection points are handled by simply processing each track line independently — if two lines cross and two nodes end up very close together at a junction, this is intentional and makes junctions look correctly dense.

### The 6 Factors — Quick Reference

| Factor | Key Variable | High When | CII Impact |
|---|---|---|---|
| Braking Zone | `brakingZone` | Within 500m of a station | −20 × value |
| Load Stress | `loadStress` | Within 15km of city center | −15 × value |
| Curvature | `curvatureStress` | `sin(d×5) > 0.8` | −12 × value |
| Moisture | `moistureIndex` | Based on longitude noise | −10 × value |
| Thermal | `thermalGradient` | Random (mild Bangalore climate) | −5 × value |
| Track Change Point | `trackChangePoint` | Within 100m of a station | −15 (flat penalty) |

### Tuning the Weights

If the demo looks too red (too many CRITICAL): Reduce the multipliers slightly, e.g., change `brakingZone × 20` to `brakingZone × 16`.

If the demo looks too green (not enough WARNING/CRITICAL): Increase `ageMonths` range or the braking multiplier.

The target distribution for the demo is roughly:
- 60% NOMINAL (Green)
- 25% WARNING (Yellow)
- 15% CRITICAL (Red)

## SECTION 6: The Map — Frontend Integration Guide

### Map Library
The frontend must use **Mapbox GL JS** via `react-map-gl`. This is the only library that supports WebGL Circle Layers (GPU rendering) for smooth performance with 3,000 dots, AND allows hiding roads/buildings via a custom style.

### Mapbox Setup (3 steps)
1. Create a free Mapbox account at https://mapbox.com
2. Go to **Mapbox Studio** → Create a new style based on "Monochrome" or "Dark Matter".
3. In the Layers panel, set opacity to 0 for: `Road network`, `Building`, `Landuse`, `Water labels`. Keep `Place labels` and `Country/City labels` visible. Publish the style and copy the **Style URL**.

### The Three-Layer Map

**Layer 1: Track Lines**
Load the `railway-network.geojson` file directly into the frontend (copy it to the public folder). Render it with:
```js
<Source type="geojson" data={railwayGeoJson}>
  <Layer
    type="line"
    paint={{ 'line-color': '#3a4a6b', 'line-width': 2 }}
  />
</Source>
```

```js

```

**Layer 3: Component Dots (Circle Layer — GPU)**
After clicking a sector, fetch components and render using a Mapbox Circle Layer (NOT React `<Marker>` components — those use the DOM and will lag):
```js
<Source type="geojson" data={sectorsGeoJson}>
  <Layer
    type="circle"
    paint={{
      'circle-radius': 5,
      'circle-color': [
        'match', ['get', 'status'],
        'CRITICAL', '#ff3c3c',
        'WARNING',  '#ffc800',
        'NOMINAL',  '#3cc87a',
        '#888888'  // fallback
      ]
    }}
  />
</Source>
```

### Station Nodes
Stations should render as a separate larger circle layer (radius 10, distinctive cyan/gold color) loaded from the station features in the GeoJSON.

### The Inspector Popup
Use the Mapbox `<Popup>` component. It automatically positions next to the clicked dot.
```jsx
{selectedComponent && (
  <Popup longitude={selectedComponent.location.lng} latitude={selectedComponent.location.lat}
    closeButton={true} anchor="left">
    <InspectorPanel component={selectedComponent} />
  </Popup>
)}
```

### The Time Slider
A simple HTML `<input type="range" min="0" max="24" />` in the Command Center footer. On `onChange`, call `GET /api/admin/predictive-map?monthsForward={value}` and update the Circle Layer data source.

    }

  return () => evtSource.close();

## SECTION 7: Docker (For Demo Laptop Deployment)

To run on the presentation laptop without any installation issues, use Docker.

### Step 7.1: Create `Dockerfile` in `/backend`
```dockerfile
FROM node:18-alpine
WORKDIR /app
COPY package*.json ./
RUN npm install
COPY . .
EXPOSE 3000
CMD ["node", "index.js"]
```

### Step 7.2: Create `docker-compose.yml` in the root folder
```yaml
version: '3.8'
services:
  backend:
    build: ./backend
    ports:
      - "3000:3000"
    environment:
      - PORT=3000
      - GEMINI_API_KEY=${GEMINI_API_KEY}
    volumes:
      - ./backend/data:/app/data
```

### Step 7.3: Run on Demo Laptop
```bash
# On demo laptop (must have Docker installed):
docker compose up --build
```

> **Important:** The `historical_components.json` must be generated BEFORE building the Docker image. Run `node scripts/generateData.js` first, then Docker.

## SECTION 9: Known Gotchas & How to Handle Them

| Issue | Cause | Fix |
|---|---|---|
| `GeoJSON file not found` error | `railway-network.geojson` missing from `/data` | Re-download from Overpass Turbo |
| Component count is 0 | GeoJSON has no `LineString` features | Re-export from Overpass Turbo, check the query |
| Map dots don't appear on tracks | Frontend rendering with `<Marker>` instead of Circle Layer | Switch to Mapbox GeoJSON Source + Layer |
| Sector endpoint returns 0 results | Sector name URL mismatch | Check `contracts.md` Section 3 for exact `sectorId` format |
| Demo trigger SSE not received | Frontend not connected to `/live-stream` | Check `useEffect` SSE connection and browser console |
| Gemini API key error | `.env` not loaded or key missing | Verify `.env` file exists in `/backend` and has the correct key |
| Port 3000 already in use | Another process using the port | Run `kill $(lsof -t -i:3000)` or change PORT in `.env` |
